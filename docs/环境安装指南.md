# Mac 和 VS Code 环境安装

适用于组员 clone 本仓库后配置开发环境。整理于 2026 年 10 月 26 日。版本为项目原来使用的组合，并非对所有新电脑的兼容保证。

## 1 安装范围

客户端使用 Flutter、Dart、Android SDK；单片机使用 ST 官方 VS Code 工具、CMake、Ninja、GNU Tools for STM32。只做安卓时不用安装完整 Xcode 和 iOS 平台；不要求 Qt、Keil、Windows 虚拟机、数据库或云服务器。

在“关于本机”确认 Apple Silicon 或 Intel，下载对应架构的软件。Apple Silicon 模拟器选兼容的 ARM64 镜像；Intel 选兼容的 x86_64 镜像。

## 2 基础工具

安装 [VS Code](https://code.visualstudio.com/download)，移入“应用程序”。命令面板运行 `Shell Command: Install code command in PATH`，重新打开终端。

```sh
xcode-select --install
git --version
code --version
python3 --version
```

Command Line Tools 已装时不重复安装。Python 脚本只使用标准库，建议 Python 3.10 以上；没有 Python 时从 [官方 Mac 下载页](https://www.python.org/downloads/macos/) 安装受支持的稳定版，不需要 Anaconda 或 pip 科学计算包。

## 3 Flutter

从 [Flutter SDK 归档](https://docs.flutter.dev/install/archive) 下载 macOS 对应架构的 stable 3.41.6，解压至 `~/FlutterSDK/flutter`。项目 Dart 基线为 3.11.4，SDK 内已包含 Dart。

在 ~/.zprofile 中加入，已有设置不要重复：

```sh
export PATH="$HOME/FlutterSDK/flutter/bin:$PATH"
export ANDROID_HOME="$HOME/Library/Android/sdk"
export PATH="$ANDROID_HOME/platform-tools:$ANDROID_HOME/emulator:$PATH"
```

```sh
source ~/.zprofile
flutter --version
code --install-extension Dart-Code.flutter
```

Flutter 扩展同时安装 Dart 扩展，见 [官方 VS Code 指南](https://docs.flutter.dev/tools/vs-code)。重新启动 VS Code。仓库不固定 dart.flutterSdkPath；自动发现失败时在个人用户设置配置自己的绝对路径。

## 4 Android

安装 [Android Studio](https://developer.android.com/studio)，完成首次向导。日常写代码可使用 VS Code，但保留 Android Studio 提供的 SDK、JDK 和模拟器。

SDK Manager 中确认：

- Android API 36 SDK Platform。
- Build-Tools 35.0.0、Platform-Tools、Command-line Tools。
- 使用模拟器时安装 Android Emulator 和一份兼容系统镜像。

项目固定 Gradle 8.13、AGP 8.11.2、Kotlin 2.0.21，Gradle wrapper 随仓库提供，不必单独安装 Gradle。版本兼容参考 [AGP 8.11 官方说明](https://developer.android.com/build/releases/agp-8-11-0-release-notes)。

原电脑装过 NDK 27.0.12077973；工程未显式锁定 ndkVersion，并关闭了 Flutter 空 CMake 构建。先尝试构建，若报缺 NDK 再装错误明确要求的版本。Flutter SDK 自身的默认 NDK 不一定与旧记录一致。

```sh
flutter config --android-sdk "$HOME/Library/Android/sdk"
flutter doctor -v
flutter doctor --android-licenses
```

优先复用 Android Studio 自带 JDK，原环境为 JDK 21。若 Flutter 找不到或误用旧 JDK，并确认此目录存在，再执行：

```sh
flutter config --jdk-dir "/Applications/Android Studio.app/Contents/jbr/Contents/Home"
```

SDK 目录以 SDK Manager 实际显示为准。工程 `android.builder.sdkDownload=false` 禁止自动补装组件；缺什么到 SDK Manager 手动安装。SDK Tools 勾选 Show Package Details 可选择具体版本。

用 Device Manager 创建并启动一个安卓模拟器，或连接开启 USB 调试的安卓真机。运行：

```sh
flutter devices
adb devices
```

以 Android toolchain 和实际设备检查为准；只做安卓无需为了 doctor 中 Xcode/Chrome 未安装而下载它们。通用步骤见 [Flutter Android 配置](https://docs.flutter.dev/platform-integration/android/setup)。

## 5 克隆并验收客户端

```sh
git clone https://github.com/pot-oie/smart-home.git
cd smart-home/客户端/home_observer
flutter pub get
flutter analyze
flutter test
flutter devices
flutter run -d emulator-5554 -t lib/main.dart
```

设备 ID 按实际替换。首次依赖下载使用联网 pub get，不使用 --offline 或 pub upgrade。VS Code 可打开本目录，选择安卓设备，按 F5 运行；fn+F5 适用于把 F 键用于系统功能的 Mac。看到页面且能交互，才算运行通过。

Flutter 会生成本机 android/local.properties。若遇路径错误，确认 sdk.dir 和 flutter.sdk 是自己电脑的 SDK 路径；这个文件不提交 Git。保留 pubspec.lock 与 Podfile.lock，不提交 build、.dart_tool 和 Pods。

## 6 STM32

安装 ST 官方扩展包：

```sh
code --install-extension stmicroelectronics.stm32-vscode-extension
```

按照扩展的工具管理器提示，实际下载 GNU Tools for STM32、CMake、Ninja、Programmer、调试和器件支持包。[官方扩展说明](https://marketplace.visualstudio.com/items?itemName=stmicroelectronics.stm32-vscode-extension)介绍当前按 bundle 下载工具的方式。不需要再重复安装完整独立 CubeIDE 与旧 CubeCLT。

历史验证组合：GNU Tools 14.3.1+st.2、CMake 4.4.0、Ninja 1.13.2、Programmer CLI 2.23.0。扩展已装不等于编译器已下载，F1 驱动包也不能代替 GCC。

修改引脚或时钟时，从 [CubeMX 官方页面](https://www.st.com/en/development-tools/stm32cubemx.html) 安装对应架构 CubeMX，项目原版为 6.18.1；在软件包管理界面安装 STM32CubeF1 V1.8.7。现有工程已含 Drivers，可先直接编译，不要为验证环境重新生成正式工程代码。

在仓库根目录运行：

```sh
python3 tools/build_firmware.py --project sensors
python3 tools/build_firmware.py --project rfid
```

输出分别为 `硬件/温湿度与光照/build/Debug/home_observer_board_test.elf` 与 `硬件/RFID/build/Debug/home_observer_board_test.elf`。新电脑重新构建，不复制 CMakeCache。脚本从本机 ST 工具目录发现工具，不需要修改版本写死的路径。变量覆盖方式见根 README。

构建不要求连接开发板，不会烧录。真实读数、接线与版本约束见 [协作与联调](协作与联调.md)。

## 7 常见问题

- flutter 找不到：检查解压位置、PATH，重开 VS Code；个人设置中可指定 SDK。
- 没有设备：先启动模拟器，看 adb devices；真机需在手机允许调试，多设备时指定 ID。
- 缺 SDK、Build-Tools 或 NDK：到 SDK Manager 按错误点名版本安装，不反复重装 Flutter。
- pub 或 Gradle 下载超时：保留完整报错，核查网络、代理、证书；国内网络可参考 [Flutter 官方中文说明](https://docs.flutter.cn/community/china)。
- CMake 或 GCC 找不到：确认 ST bundle 下载完成，或按 README 设置工具绝对路径。终端无全局 GCC 命令不代表 ST 内工具未安装。
- ST-LINK 连接失败：关掉其他占用程序，核对线材、供电和 SWD。不要用擦除 Flash 作为通用修复。

从零配置两套环境建议预留约 25 至 40 GB 磁盘作为规划余量，实际随 SDK、镜像与缓存变化。一个模拟器即可，安卓真机可减少镜像占用；完整 Xcode 留到做 iOS 时再装。

## 8 交接验收

- git、code、python3 与 flutter 命令可用，Flutter 版本为组内约定版本。
- flutter doctor 的 Android toolchain 可用，flutter devices 识别目标。
- pub get、analyze、test 成功，VS Code F5 打开可交互的模拟客户端。
- 涉及固件开发时，两套 Debug 工程编译成功。
- 不把模拟页面、构建成功或 RFID 轮询当成所有实物均验收通过。

向组内回传版本、doctor/devices 输出与运行截图；错误附完整日志。安装流程没有必要执行烧录。
