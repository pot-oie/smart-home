# 协作与硬件联调

## 分支协作

组员先 clone 并按安装指南跑通 main.dart。每次开始工作先更新 main，再创建功能分支，例如：

```sh
git switch main
git pull --ff-only
git switch -c feature/rfid-status
```

完成修改后提交、推送分支并发起 PR。公开仓库人人可 clone；直接推送仍需要仓库写权限，组员没有权限时可以 fork 后提 PR。不要提交 local.properties、签名密钥、Flash 备份和个人 SDK 路径。

## 固件和读取脚本必须成套使用

温湿度与光照工程：H02 使用 DHT12 格式 I²C 帧，H03 为 BH1750 数字光照。两路已做过持续采样和遮挡响应验证。RFID 工程新增 RC522；目前只确认固件写入，读卡没有成功。

两套工程输出的 ELF 名称相同，但内容和符号地址可能不同。只读 RAM 时必须使用与板上烧录内容对应的 ELF；重新编译的文件不能自动视为板上现存固件的符号依据。提交后烧录时，个人记录 Git commit、ELF SHA256、实际接线及结果，原程序备份单独保存在本地。

Python 读取脚本不需要 pip 依赖。在对应固件目录执行：

```sh
# 温湿度与光照工程
python3 tools/read_sensors.py --count 3

# RFID 工程
python3 tools/read_rfid.py --count 3
```

关闭其他 ST-LINK 调试、烧录和读数进程再运行。首次安装不要求连接或烧录实物。

## 已用接线

以下按已识别的课程板与模块整理；其他板卡需重新核对丝印、电平和供电。断电接线。

| 模块引脚 | STM32 引脚 |
| --- | --- |
| H02 DHT12 + / − | 3.3V / GND |
| H02 SDA / SCL | PB7 / PB6 |
| H03 GY-30 VCC / GND | 3.3V / GND |
| H03 SDA / SCL | PB7 / PB6 |
| H03 ADD | GND，选择地址 0x23 |
| RC522 3.3V / GND | 3.3V / GND |
| RC522 SDA 片选 / SCK | PA4 / PA5 |
| RC522 MOSI / MISO | PA7 / PA6 |
| RC522 RST / IRQ | PB0 / 不接 |

H02 地址 0x5C；这里 RC522 的 SDA 丝印表示 SPI 片选，不应接到传感器 I²C SDA。RC522 与板卡供电仍需继续排查，表格不代表 RFID 实物通过。

## 安卓真实读数入口

前提：兼容的双传感器固件已经在板上运行，两个模块已正确连接，仓库中 ELF 与板上程序一致。默认网关指向仓库里的 `硬件/温湿度与光照`；可用 HOME_OBSERVER_BOARD_PROJECT 环境变量选择其他匹配工程。

在客户端目录终端一执行：

```sh
python3 -u tools/swd_gateway.py
```

终端二执行，使用自己的设备 ID：

```sh
adb -s emulator-5554 reverse tcp:8765 tcp:8765
flutter run -d emulator-5554 -t lib/main_hardware.dart
```

链路为 STM32 → ST-LINK SWD 只读 RAM → Mac → adb reverse → Android。Mac 和下载器需持续连接；模拟器重启后重建端口映射。当前真实入口展示温度、湿度、光照，不是完整模拟客户端的全部功能。RFID 无线透传未接通，不应据此声称手机可以无线控制实体设备。

## 手动烧录工具

RFID 目录保留 `tools/flash_rfid.py`，只在确认接线和供电后手动运行。它会先备份再写入并校验，记录位于仓库本地 `artifacts/`，不会进入 Git。历史上 Programmer 校验文字匹配曾造成“脚本报错但实际已写入”的情况，脚本已取消对单一英文成功短语的依赖；如果写入阶段失败，应先检查日志与实际 Flash 状态，不要盲目重复写入。
