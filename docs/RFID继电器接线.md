# R6 · RFID + 5V继电器 + USB转TTL完整接线

2026-10-28。新模块为照片中的TONG LING JQC-3FF-S-Z、5VDC单路继电器板，输入VCC/GND/IN，具体板级触发极性和3.3V兼容性尚待实测。继电器型号/5V线圈不能证明模块IN的有效电平。本轮仅用动作声和指示灯验证，右侧三个螺丝触点端子全部留空。

## 供电与面包板分组

先拔掉ST-LINK和USB转TTL的两个USB插头，断电接线。模块放在绝缘表面。使用面包板a-e半区，同一个数字的a-e五孔互通，中央槽另一侧f-j不互通；上下红蓝长电源轨本轮不用。

| 面包板孔 | 连接的器件端子 | 作用 |
| --- | --- | --- |
| 10a | STM32侧排针3.3 | 3.3V来源，STM32仍由ST-LINK供电 |
| 10b | RC522 3.3V | 读卡模块供电 |
| 15a | STM32侧排针G/GND | 公共地 |
| 15b | RC522 GND | 读卡模块地 |
| 15c | USB转TTL GND | 串口及5V电源共地 |
| 15d | 继电器GND | 继电器地 |
| 20a | USB转TTL明确标记的5V脚 | USB 5V来源，不使用可选VCC脚 |
| 20b | 继电器VCC | 5V线圈板供电 |
| 25a | STM32 B12/PB12 | 预留继电器信号，触发测试通过后再接 |
| 25b | 继电器IN | 预留继电器信号，触发测试通过后再接 |

10/15/20/25是互相独立的四组，不能用导线把3.3V与5V并在一起。USB转TTL的VCC、3V3、TXD留空；其5V仅给继电器板供电，STM32/RC522仍由原3.3V一路供电。若USB口/线材承载不足导致掉电或抖动，改用独立稳压5V供电后保持共地，不用GPIO或ST-LINK 3.3V驱动线圈。

## ST-LINK到STM32（4线）

| ST-LINK标记 | STM32四针调试口 |
| --- | --- |
| 2/SWCLK | SWCLK |
| 4/SWDIO | SWIO |
| 5/GND | GND |
| 7/3.3V | 3V3 |

按实物丝印，不按照片左右数脚。该连接用于烧录和现有供电，运行数据仍走USB转TTL。STM32自身Micro-USB不另接。

## RFID和上传信号（6线）

| 器件端子 | STM32侧排针 |
| --- | --- |
| RC522 SDA（SPI片选） | A4/PA4 |
| RC522 SCK | A5/PA5 |
| RC522 MOSI | A7/PA7 |
| RC522 MISO | A6/PA6 |
| RC522 RST | B0/PB0 |
| USB转TTL RXD | A9/PA9 |

RC522 IRQ留空。NodeMCU黑板、温湿度、光照本轮不接。信号线直接连接，避免不可靠的母头对母头转接。

## 线材数量

按排针接口计算：ST-LINK4根母对母，RC522五根信号+串口一根信号共6根母对母；8根电源/地公对母。触发测试通过后，B12→25a与IN→25b再增加2根公对母。合计约10根母对母、10根公对母，可多准备2根备用。若模块端实际是排母插座，按实物改用能插入的公头。

## 上电前的继电器触发确认

先完成上表电源、地、RC522和串口，25a/25b暂不接。使用一根公对母测试线，母头接继电器IN。

1. 另一头插15e（GND），插入两个USB，上电观察SW灯与是否吸合。
2. 再拔掉两个USB；将该测试线从15e移到10c（STM32的3.3V组），重新上电观察。
3. 回报IN接GND和3.3V时分别的吸合/释放状态。只改这根IN测试线，不动其他线。

若GND释放、3.3V吸合，可配置高电平触发；若GND吸合、3.3V释放，可配置低电平触发。若两者均吸合、均释放或抖动，暂不把IN接主控GPIO，需要继续核对电平或补电平转换。不能只根据电源红灯推断吸合，优先看SW指示和开关动作。

助手确认后，断电移除IN测试线，按25a/25b接上最终B12控制线，并设置对应BOARD_RELAY_MODE、编译、备份烧录、回读验证。

## 程序行为与验证

目前按“任意有效UID识别成功→吸合约3秒→自动释放”实现，尚未做授权名单判断。根据g_rfid.event_seq触发，同一卡连续停留不会不断续期；新刷卡事件会重新开始3秒计时。上电输出先置释放状态，再启用GPIO。实际释放时刻受现有轮询/串口发送影响，不宣称精确到毫秒。

relay_pulse.c的主机测试覆盖：无卡不吸合、同事件不续期、3秒释放、新事件重触发、32位计时溢出。高低触发GPIO配置均编译通过；主构建默认BOARD_RELAY_MODE=0，暂不驱动GPIO。尚未烧录新程序或完成继电器实物验证，原UART固件仍在板上。

接线验收后再做：不刷卡时释放→刷卡时吸合→约3秒释放→同卡停留不重复→移开再刷再吸合→USB串口卡号仍正常上传。触点空载时不会给外部负载供电，本轮不接市电。

资料：[Tongling JQC-3FF系列原厂产品资料](https://en.tonglingrelay.com/product/JQC-3FF-S-Z-12VDC-12V-Relay-5-Pin-1156.html?productCateId=53)用于核对继电器系列，不作为未知驱动板触发极性的证据；供电标称以本次实物5VDC为准。


## 已全部接线时的软件诊断路径

若已按25a/25b把PB12接至IN，用户不必再反复挪IN测试线。助手可以先构建`python3 tools/build_firmware.py --project rfid --relay-mode probe`并备份烧录；诊断程序默认输出LOW，用户回报绿色SW灯亮/灭，再由助手用`tools/relay_probe.py --level 1`切HIGH并回读PB12电平，让用户再次观察。该工具仅在已匹配的诊断固件下改命名SRAM变量，不是运行时上传链路。

确认LOW/HIGH分别的实际状态后，再构建`--relay-mode high`或`--relay-mode low`并烧录3秒刷卡功能。`--relay-mode off`为默认未启用状态，不能把probe诊断模式当作正式联动。
