# 接线总表与接手复现

更新：2026-10-28。依据已用接线、实物标记和已完成记录整理；[器件与版本](器件与版本.md)提供H编号和照片，[交接文档](../HANDOFF.md)提供功能边界。各信号以模块及主控丝印为准，线色不定义功能。

## 1. 当前使用方案：RFID + USBTTL + 继电器（R6）

温湿度与光照在此次RFID联调阶段未接，NodeMCU未接。主控由ST-LINK现有3.3V路线供电，继电器由USBTTL明确5V端供电，两路共地。换线前拔掉两侧USB。上电先接ST-LINK给主控供电，再接USBTTL给继电器供电；断电顺序相反。STM32自身Micro-USB不另接。

### ST-LINK到主控：4根母对母

| ST-LINK外壳功能编号 | STM32四针调试口 | 用途 |
| --- | --- | --- |
| 2 SWCLK | SWCLK | SWD时钟 |
| 4 SWDIO | SWIO | SWD数据 |
| 5 GND | GND | 地 |
| 7 3.3V | 3V3 | 现有供电 |

只按实物丝印与已核对针序追线，不按照片左右数脚。5V不接主控3V3。

### RFID与UART信号：6根母对母

| 模块端 | STM32侧面丝印/信号 |
| --- | --- |
| RC522 SDA（SPI片选） | A4 / PA4 |
| RC522 SCK | A5 / PA5 |
| RC522 MOSI | A7 / PA7 |
| RC522 MISO | A6 / PA6 |
| RC522 RST | B0 / PB0 |
| USBTTL RXD | A9 / PA9，USART1_TX |

RC522 IRQ空；USBTTL TXD、可选VCC、3V3空，单向上传不使用PA10。

### R6面包板分线：a-e半区

| 孔位 | 接入端 | 含义 |
| --- | --- | --- |
| 10a | STM32侧面3.3V | 3.3V来源 |
| 10b | RC522 3.3V | RFID供电 |
| 15a | STM32 G/GND | 公共地 |
| 15b | RC522 GND | RFID地 |
| 15c | USBTTL GND | 串口/电源共地 |
| 15d | 继电器GND | 继电器地 |
| 20a | USBTTL明确5V端 | 5V来源 |
| 20b | 继电器VCC | 继电器供电 |
| 25a | STM32 B12/PB12 | 控制信号 |
| 25b | 继电器IN | 控制输入 |

10/15/20/25互相独立，同编号a-e五孔内部相通，f-j另一半不与a-e相通；本方案不用长电源轨。RC522仅接3.3V；不要并联3.3V与5V。继电器螺丝触点三端目前空载。

上述按10根母对母和10根公对母准备，可增加备用线；模块接口如非公排针按实物调整。仅运行RFID+USBTTL时可去掉继电器及20/25组，USBTTL 5V留空。

### 控制方式与验收

此继电器已实测PB12开漏低有效：拉低吸合、释放高阻后释放。推挽输出3.3V不能可靠释放，因此不套用推挽低有效接法。当前已烧录`--relay-mode low`；构建默认off，probe是诊断模式。GPIO读回不代替触点/机械动作反馈。

尚需验收：无卡释放→新有效读卡吸合约3秒→自动释放→同卡停留不续期→移开再刷重触发→USB串口持续上传。当前按任意有效UID触发，尚无授权名单。操作过程与历史诊断见[继电器接线](RFID继电器接线.md)。

## 2. 温湿度与光照：独立接线或并回集成工程

H02/H03曾实测共享PB6/PB7总线；本表供恢复该组合，不能据此声称已与最新继电器方案完成整机联调。

| 模块端 | STM32端/电源 | 说明 |
| --- | --- | --- |
| H02 + / − | 3.3V / GND | DHT12格式 |
| H02 SDA / SCL | PB7 / PB6 | 地址0x5C，约2.5秒采样 |
| H03 VCC / GND | 3.3V / GND | GY-30/BH1750 |
| H03 SDA / SCL | PB7 / PB6 | 与H02共享软件I²C |
| H03 ADD | GND | 地址0x23；不能改高到0x5C与H02冲突 |

历史共享接法已通信通过，未另加上拉；板载电阻阻值未电测，换模块不能直接假定一致。湿度量程外不是通信失败；恢复后核查质量标记，不把校验通过等同于准确度校准。

### 历史R3双传感器面包板方案（与R6二选一）

| 分组 | 主控 | H02 | H03 | H03地址 |
| --- | --- | --- | --- | --- |
| 10组=3.3V | 3.3→10a | +→10b | VCC→10c | — |
| 15组=GND | G→15a | −→15b | GND→15c | ADD→15d |
| 20组=SDA | B7→20a | SDA→20b | SDA→20c | — |
| 25组=SCL | B6→25a | SCL→25b | SCL→25c | — |

**R3的20/25组是I²C；R6的20/25组是5V/继电器信号，绝不能叠加。** 如需同时接全部模块，应先画出新的独立分组表，使用不同空闲组接PB7和PB6，复核后再上电。未发布已验收的全模块同接面包板方案。

## 3. GPIO与资源占用

| 主控资源 | 已分配用途 | 后续限制 |
| --- | --- | --- |
| PA4/PA5/PA6/PA7 | RFID片选/时钟/MISO/MOSI | 不分给新增检测模块 |
| PB0 | RFID复位 | 已占用 |
| PB6/PB7 | 光照与温湿度软件I²C | 保留地址与上拉兼容性 |
| PA9 | USART1 TX上传 | PA10尚未启用，未来下行需确认电平并改代码 |
| PB12 | 继电器IN | mode2/3开漏，mode1推挽 |
| PC13 | 板载指示LED | 已占用 |
| SWD口 | 下载与调试 | 保留，不能挪作普通信号 |

H04声光、H05人体红外、H06气体、H07火焰尚无已批准/已验收的GPIO表。接手者先确认模块供电、信号上限、针序、有效电平与ADC需求再分配；H08缺探头暂不接，H09/H10/H14为可选或备用。

## 4. 运行与记录

- 运行串口接收及安卓真实入口：[USB串口上传](USB串口上传.md)。串口名和安卓ID取本机实际值。
- 烧录与读RAM必须对应同一版本ELF；Python串口网关不需要ELF。[器件与版本](器件与版本.md)记录最后确认的板上固件指纹。
- 模拟App完整四页与独立真实页面有不同入口，不能用模拟报警证明现场报警已实现。
- 接手时保存最终接线照片、版本/模式、日志及验收结果；当前照片以认物为主，尚未归档覆盖全部连线的最终整机照片。
