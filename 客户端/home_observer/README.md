# 家居观察 Flutter 客户端

项目使用 Flutter 3.41.6 / Dart 3.11.4，Android 与 iOS 工程均保留。日常运行入口为 `lib/main.dart`，所有现场数据来自 App 内模拟设备并明确标识。iOS 工程尚未完成本次验证。

完整安装步骤见 [仓库安装指南](../../docs/环境安装指南.md)，硬件当前状态和真实读数步骤见 [协作与联调](../../docs/协作与联调.md)。

```sh
flutter pub get
flutter analyze
flutter test
flutter devices
flutter run -d emulator-5554 -t lib/main.dart
```

用自己的 Android 设备 ID 替换 emulator-5554。VS Code 打开本目录，选安卓设备并按 F5 即可调试。不要先复制其他电脑的缓存或 local.properties。

`lib/main_hardware.dart` 仅显示温度、湿度、光照，依赖 Mac/ST-LINK 网关及同版本固件 ELF；无线直连尚未实现。

## 使用入口

- **首页**：温湿度、相对光强、窗帘/通行软件模拟、待处理安全事件；历史和模块入口。
- **事件**：“待处理”保留所有尚未同时恢复和确认的事件；“历史”展示已结束事件。确认仅表示知晓。
- **RFID**：授权名单管理（添加、停用、移除）、刷卡记录；模拟刷卡支持未知卡、失败及重复抑制。
- **设置**：阈值、恢复余量、持续时间、光敏滞回、自动/手动、活动布防；设置收到匹配请求的接受结果才生效。
- **设置 → 设备连接**：模拟输入、接受/拒绝/超时、断连/重连、无效/停止更新、安全输入、名单不可用及默认输入恢复。

图表只使用实际收到的模拟样本；首次运行先显示“等待更多记录”，每 5 秒形成一条历史记录，不预填过去的测量。

## 代码结构

- `lib/domain/models.dart`：模块、样本有效性、设置、事件、刷卡、请求、结果、历史。
- `lib/data/device_adapter.dart`：设备接入接口，不提前选定 BLE/Wi-Fi 或字节协议。
- `lib/data/simulator.dart`：模拟现场逻辑与双向请求，仅作未来 STM32 的行为参考。
- `lib/data/home_controller.dart`：页面共享状态、请求超时、编号匹配、事件去重、有限历史。
- `lib/data/local_store.dart`：App 文档目录中的 JSON 检查点，临时文件写入后替换。
- `lib/ui/`：四页与详情、统一视觉、真实数据曲线。
- `test/`、`integration_test/`：规则、页面与原生联调测试。

[接口与数据约定](docs/接口与数据约定.md)、[后续硬件接入](docs/后续硬件接入.md)。`pubspec.lock` 和 `ios/Podfile.lock` 为实际解析出的依赖锁文件。

## 存储与模拟边界

App 沙盒：`home_observer/checkpoint.json`；保存已生效设置、事件、刷卡、请求和历史。最近 2000 条监测点、300 个事件、200 条刷卡、50 个操作；容量超过时优先保留活动事件，已恢复但未确认的较旧事件也可能淘汰，模拟页显示丢弃计数。历史最多展示最近 50 条查询结果。

普通更新约 2 秒合并保存，进入后台时再次提交保存；不承诺强制终止、掉电或写盘失败时零丢失。读取失败显示可重试错误，保存失败显示横幅。历史以已接收样本为准，断连期间不会假装持续采集到手机。

模拟器只在 App 进程运行时推进现场逻辑；App 被挂起或杀死后不提供后台常驻保证。真实设备必须独立继续检测和有限缓存，不能依赖 App 存活。摄像头、云服务、登录、实体执行机构均未实现。
